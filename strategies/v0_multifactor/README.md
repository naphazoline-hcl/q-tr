# robust_multifactor — 低速マルチファクター + 勾配ブースティング

## 仮説

このコンペのスコアは「シグナルを日次5分位ロング・ショートに変換し、片道0.1%の
取引コスト控除後の年率Sharpe」で決まる。したがって本質は

**予測を当てること（RankIC）ではなく、コストを払わずに当てること**

にある。配布 README の対比どおり、1日リバーサルは RankIC +0.0072 で sample02 の
+0.0053 を上回るのに、回転率1.337 のコスト年率33.7%に負けてスコア −6.35 になる。

そこで、経済的に持続する（=ゆっくりしか動かない）プレミアムを土台にし、
機械学習は「長いホライズンの平均リターン」をラベルに学習させて回転率を抑える。

## 処理

### 1. 特徴量（`rf_features.py`、51列）

すべて時点 $t$ までの情報だけで構成する。決算短信は開示日基準の backward as-of join、
rolling は過去方向のみ、`shift` は正方向のみ。

| ブロック | 主な特徴量 |
|---|---|
| 規模・流動性 | `-log(時価総額)`, Amihud非流動性(20/60日), `-log(売買代金)`(20/60日) |
| バリュー | B/P, S/P, 予想E/P, 実績E/P, CF利回り, 配当利回り |
| クオリティ | ROE, 営業CF/総資産, 自己資本比率 |
| 低リスク | `-β`, `-ボラティリティ`(20/60日) |
| 価格・需給（ML用） | 短期リバーサル, モメンタム(12-1), 日中/前場/後場リターン, レンジ, 出来高比 |
| 財務モメンタム（ML用） | 売上/利益/CFの前年同期比, 予想EPSの変化・前年同期比, 開示からの経過日数 |
| 属性 | ScaleCategory, 17/33業種, 市場区分, 信用区分 |

#### 分割・併合と1株当たり財務値の基準そろえ（重要）

`AdjustmentClose` は配布データ生成時点（2026-07-31）の株式数基準へ遡って調整済み。
一方、決算短信の1株当たり財務値（BPS・EPS・予想EPS・予想配当）は**開示時点の
株式数基準**である。両者をそのまま割ると、開示日から観測日までに分割・併合が
あった銘柄だけ指標が倍率分ずれる（探索Notebookの注意点）。

本戦略では `AdjustmentClose / Close` を調整比率 $R$ として、

```
1株当たり財務値（生成時点基準） = 財務値 × R(開示日)
株数（生成時点基準）           = 株数 ÷ R(開示日)
```

と換算してから使う。$R$ は将来の分割も含むが、開示日と観測日の比だけを使うため
数式上は「観測日までに確定した分割」だけが残り、先読みにはならない。

> 検証: 同じ Train の purged walk-forward で、この換算をしない
> `AdjustmentClose × 開示時点株数` はサイズファクター SR +2.86 と出るが、
> 正しい基準そろえでは +2.16（生 `Close` を使うサンプル流でも +2.12）。
> 差分は「将来分割する銘柄を小型・割安と誤認して買っていた」分であり、
> 実力ではない。本戦略はこの換算を行う。

### 2. ラベル設計（コストへの対処）

モデルの学習ラベルを翌日1日リターンではなく、**翌日から k 営業日の平均残差リターン**
にする（`k = 126` と `k = 250` の2本、クリップ ±5%）。

```
label[t] = clip( mean(target[t], target[t+1], ..., target[t+k-1]), -0.05, +0.05 )
```

ラベルを将来平均にすると、モデルは数ヶ月スケールの優劣を学び、シグナル自体が
ゆっくり動く。日次の建玉変化（回転率）が減り、コストが激減する。学習ラベルは
Train の target のみで作る（Valid のラベルは一切使わない）。

### 3. モデル

LightGBM 回帰（350本、learning_rate 0.03、num_leaves 31、min_child_samples 300）。
特徴量は日次断面で順位化し、セクター列はカテゴリとして使う。シード3つ×ホライズン2つ
の計6モデルの予測平均をシグナルにする。

### 4. 合成と平滑化

```
signal = 1.0×z(size) + 0.5×z(value) + 0.5×z(quality) + 0.3×z(lowrisk)
       + 0.5×z(model)
```

各ブロックは符号付き断面順位の等ウェイト平均。最後に銘柄ごとに EWMA(span=5) で
平滑化して回転率をさらに落とす。

## 検証方法（Valid のラベルを使わない）

方針の決定はすべて Train 期間（2008-11〜2016-03）内で行った。

- **Purged walk-forward**（2010〜2015 の各年を順に検証。学習の未来ラベルが
  検証年のリターンを参照しないよう、境界の k 営業日を学習から除外）で
  ホライズン・モデル容量・ブロック重み・モデル重み・平滑化を選択
- Valid（2016-04〜2026-07）はスコアを確認するだけで、選択には使っていない

### Train 上の主な比較（purged walk-forward、span=5 のネット年率Sharpe）

| 戦略 | Train OOS (2010-2015) | 備考 |
|---|---|---|
| 1日リバーサル | コスト負け | サンプル01の Valid は −6.35 |
| LGBM（1日ラベル, 平滑化なし） | −1.79 | RankIC +0.027 でもコスト年率19% |
| LGBM（k=126ラベル, purge, span5） | +1.34 | ラベルを長期平均にすると回転率 0.047 |
| LGBM（k=250ラベル, purge, span5） | +1.44 | |
| 規模ブロック（サイズ+非流動性+売買代金） | +1.99 | |
| クオリティブロック | +1.11 | |
| 低リスクブロック | +0.59 | |
| バリューブロック | +0.25 | 基準そろえ後は弱い |
| 本戦略（ブロック + モデル0.5 + span5） | **約 +2.4** | |

「1日ラベル LGBM」は予測精度が高いのにコストで負ける。ラベルを長期平均に
変えるだけで同じモデルが +1.3〜1.4 まで回復し、ブロック合成と混ぜると +2.4 になる。

## Valid 期間の実測（2016-04-01〜2026-07-31）

```
SHARPE          : +0.754
グロス年率      : +3.42%
コスト年率      : +0.43%   （日次回転率 0.0169）
年率ボラティリティ: 3.98%
日次勝率        : 52.6%
RankIC          : +0.0084
```

年別Sharpe: 2016 +1.35 / 2017 +3.04 / 2018 +1.62 / 2019 +0.96 / 2020 −0.32 /
2021 −0.51 / 2022 +1.29 / 2023 +1.73 / 2024 +0.42 / 2025 +0.39 / 2026(途中) −0.22

グロス +3.4% に対してコストが 0.43% しか乗らない設計が効き、11年中7年プラス。
2020〜2021年のグロース相場でサイズ・バリューが振るわず負けているのが主な弱点。

## 実行方法

```bash
# 1) モデル学習（models/*.txt と meta.json を更新）
python strategies/robust_multifactor/train.py --data-dir input

# 2) ローカル採点
python evaluate_script.py --submission strategies/robust_multifactor
```

採点時の実行時間はローカルで約90秒（モデル読込・特徴量構築・推論・平滑化を含む）。
CPUのみで完結し、GPUは使わない。

採点環境のリソース上限に当たらないよう、parquet は pyarrow の predicate pushdown で
`Date` / `Code` を読む前に絞り、`listed_info` は全上場約4,400銘柄ではなくユニバース
498銘柄×必要5列だけを読む。特徴量・順位・推論行列は float32 で保持し、ピークメモリは
ローカルで約1GB台に収まる（初版は約8.7GBで、採点がリソース上限に当たる可能性があった）。


## 限界と改善案

- グロス +3.4% は既知プレミアムへの露出が中心。2020〜2021年のような
  グロース優勢局面では負ける（サブ期間Sharpe: 2018-2021 +0.38）
- 現実の売買コストは小型・低流動性ほど高いが、採点は一律0.1%なので
  流動性プレミアムの見かけの優位が残る
- 改善案: 財務のTTM化、セクター中立化、kホライズンの乱数アンサンブル、
  マクロ局面によるブロック配分（sample05型）。いずれも Train 内
  purged walk-forward で判断する
