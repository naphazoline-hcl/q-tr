## 2. 根拠（S3 の実測結果から）

### ① 回転率: コストで負けている（RankIC や分位の問題ではない）

- I1 のコストは `0.1% × 0.0216 × 252 = 0.544%/年` で、実測の 0.54% と一致する。v1 の回転率 0.0169 なら 0.426%/年。
  **回転率の増分だけで年 0.118% のコスト増**になる。
- docs/baseline.md の Valid 実測では、グロスは **I1 +3.47% > v1 +3.42%** で I1 が上、コストは 0.54% vs 0.43%。
  **I1 が v1 に負けたのはコスト（回転率）だけ**で、シグナルの稼ぎは負けていない。
- I1 の vol は `net / SR = (3.47 − 0.54) / 0.747 ≈ 3.92%/年`。回転率 0.017 でグロスと vol が I1 と同じなら
  Sharpe は `(3.47 − 0.428) / 3.92 ≈ 0.776`。v1（0.754）に勝つには、平滑化で失ってよいグロスが
  **年 0.084% 以下（I1 の約 2.4%）**に収まる必要がある。
- 回転率の出どころも実測で特定できる（baseline.md のアブレーション）: A → I1（中立化項を追加）で
  Valid 回転率 0.0182 → 0.0216、Train OOS 回転率 0.0224 → 0.0298。A → I3（model_weight 0.25）で
  Train OOS 回転率 0.0224 → 0.0193。**回転はモデル由来の項から出ている**。
- I1 は中立化項（`sector_weight 0.5`）を足したことで、モデル由来の重みが v1 の 0.5 から実質 1.0 に増えた。
  モデル入力（`model_features: "v1"`）には 1〜10 日窓の列（r1, rev1, rcc3/5/10, range1, clv1, volratio など）が
  入っており、MODEL_DESIGN.md でも「回転率を上げるだけになりやすい」と記録されている。
  ブロック（60 日窓・財務）は遅いので、**モデル成分だけを遅くする** `model_smoothing_span` を採った。
- span 10 の平均遅れは `(10 − 1) / 2 = 4.5 営業日` で、ラベル窓 126 / 250 日の約 3.6% / 1.8%。
  span 20 なら 9.5 日（7.5% / 3.8%）。この比較から既定は **10**、20 と 40 はスイープで実測して比べる。
  **回転率がいくつになるかは `{要実行}`。**

### ② 2017 / 2019 / 2025 の劣化（仮説。検証方法つき）

- 分位（bp/日）: Q1 −0.39 / Q2 +0.65 / Q3 −0.03 / Q4 +1.33 / Q5 +3.37。採点の重みは分位あたり `(q − 2) / 6` なので、
  グロスは `(2·Q5 + Q4 − Q2 − 2·Q1) / 6 = 1.367 bp/日 ≈ 3.44%/年`（実測 3.47% と整合）。
  両端（Q1・Q5）が約 92% を稼ぎ、Q2 が Q3 より高い（ショート側の中央が逆に動く）。中央の入れ替わりは
  アルファを生まずにコストだけを生むので、①の平滑化と同じ方向の対策になる。
- 年別: I1 は 2020（−0.28 vs v1 −0.32）・2021（−0.18 vs −0.51）・2022（+1.53 vs +1.29）で v1 を上回ったが、
  2016（+1.14 vs +1.35）・2017（+2.88 vs +3.04）・2019（+0.84 vs +0.96）・2025（+0.23 vs +0.39）で下回った。
  この差 0.12〜0.21 は、コスト増の平均的な重さ（0.118 / 3.92 ≈ 0.03）の 4〜7 倍あるので、
  **これらの年はコストではなくグロス（シグナル）で負けている**。
- 業種ローテーションの年に効き、業種への賭けが報われた年に負ける形で、
  **中立化（モデル中立化項 + size / value の業種内順位）が業種間リターンを手放した**ことと整合する。
- 順位の逆転は v1 → A の段階で起きている（Train OOS +1.993 → +2.192、Valid +0.754 → +0.698）。
  この段階の差分は「size / value の業種内順位」「horizon z」「strict ラベル」。A → I1（中立化項）は
  Valid +0.049・Train OOS −0.108 で、Valid には効いている。
- 検証: `sweep_improve1.py` が Valid の年別グロスを**業種間（業種平均リターンへの賭け）と業種内（銘柄選択）**に
  分け、I1 / K1 / v1_like / no_sector_rank_blocks で比べる。単独成分（size・value・quality・lowrisk・
  model・model_sector）の年別 Sharpe も出すので、2017 / 2019 / 2025 に崩れた成分が特定できる。`{要実行}`

### ③ horizon_combine z と strict ラベルの切り分け

- strict ラベルでは fold 2010 が学習 0 行、fold 2011 が k126 だけになる（S3 の注記）。Train 全期間の最終モデルでも、
  直近 125 / 249 営業日はラベルが無い。v1 は境界付近の短い窓も使っていた（`partial` として再現した）。
- `sweep_improve1.py` が 2×2（strict / partial × z / mean）を同じ fold・同じ seed で作り、
  Train OOS Sharpe・Valid Sharpe・Valid 回転率のそれぞれについて **z の寄与・strict の寄与・交互作用**を出す。`{要実行}`
