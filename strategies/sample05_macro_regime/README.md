# sample05_macro_regime — マクロレジームによるファクターローテーション

## 仮説

まず、マクロ変数の使い方は様々あるが、ここでは最も簡単な例として
レジーム（局面）の判定に用いる。

そのうえでの仮説は以下のように設計。
家計の景況感が悪化している局面では、投資家は業績の下振れを警戒して
財務が頑健で現金を稼げる企業にプレミアムを払う。
景況感が良い局面では、リスクを取って割安株を拾いにいく。
だからクオリティとバリューの配分は景況感で変えるべき、ということになる。

## 処理

1. クオリティとバリューは sample03 と同じ定義
2. `consumer_attitude_index` を読み、過去750営業日（約3年）の平均・標準偏差で標準化する
3. 配分係数を作って合成する

```
w      = clip(−DI_z / 2, −1, +1)
signal = (1 + w) × クオリティ + (1 − w) × バリュー
```

`w = 0` で等ウェイト、`w = +1` でクオリティのみ、`w = −1` でバリューのみ。

### マクロ系列の結合で間違えやすい点

`consumer_attitude_index` の `Date` は観測月ではなく、その値が利用可能になった日時
（Asia/Tokyo, **23:59:59**）である。配布README にこう書かれている。

> e-Statは過去原本に公表日しかないため、同日先読みを避けて23:59:59 JSTから利用可能としています。

つまり「その日の取引時間中には、まだこの値を知らない」という設計になっている、という点に注意が必要。


```python
macro["Date"] = macro["Date"].dt.tz_convert("Asia/Tokyo").dt.tz_localize(None)
macro["Date"] = macro["Date"].dt.normalize()   # ← ダメ
```

`normalize()` は `2020-05-13 23:59:59` を `2020-05-13 00:00:00` に丸めてしまう。
その日の朝からこの値を知っていたことになり、配布側の先読み防止が無効になる。

正しくはこう。

```python
macro["Date"] = macro["Date"].dt.tz_convert("Asia/Tokyo").dt.tz_localize(None)
merged = pd.merge_asof(pd.DataFrame({"Date": trading_days}), macro,
                       on="Date", direction="backward")
```

営業日は `00:00` なので、`23:59:59` の値はそれより後になり、翌営業日から使われる。
`ecb_fx_rates` も同じ（フランクフルト16:00公表 → 夏時間は23:00 JST、冬時間は翌日00:00 JST）。

3年ローリングの標準化には Train 期間の履歴が必要なので、
Train のマクロ系列も連結してから計算し、最後に Valid の行だけを返している。

## 考えたこと・分析

スコアは **+0.80**。固定配分の +0.55 に対して上がった。

| | 回転率 | RankIC | スコア |
|---|---|---|---|
| クオリティ固定 | 0.015 | 0.0039 | +0.29 |
| バリュー固定 | 0.026 | 0.0034 | −0.03 |
| 等ウェイト固定（= sample03） | 0.033 | 0.0062 | +0.55 |
| 消費者態度指数で配分切替 | 0.036 | 0.0091 | +0.80 |
| 仮説と逆向きに切替 | 0.033 | −0.0005 | −0.39 |

回転率はほとんど増えていない（0.033 → 0.036）。
配分の変化が月次かつ緩やかなので、レジームごとにシグナル計算方法を変えても、コストがかからない。

逆向きにすると −0.39 になることも確認している。
仮説の方向にだけ効いて逆向きでは壊れる、という非対称性があってはじめて、
「景況感が悪いときはクオリティ」という筋に意味が出る。

年で見ると2020年が +15.5% と突出していて、クオリティに全振りしていた局面と一致する。
一方2017・2018・2021・2022年はマイナスで、最大ドローダウンも他のサンプルより深い。
局面を当てにいく分だけ、ぶれも大きくなっていると考えられる。

## 効かなかった仮説: 為替

同じ枠組みを `ecb_fx_rates` でも試した。

> 円安が進む局面では輸出企業の業績期待が上がるので、外需セクター
> （自動車・機械・電機精密・素材化学・鉄鋼非鉄）が内需セクター
> （食品・小売・情報通信サービス・電気ガス・不動産）に対して強い。

| | 回転率 | RankIC | スコア |
|---|---|---|---|
| 外需/内需 × USDJPY 1ヶ月変化 | 0.193 | +0.0016 | −0.68 |
| 外需/内需 × USDJPY 3ヶ月変化 | 0.083 | +0.0021 | −0.31 |
| 外需/内需 × USDJPY 12ヶ月変化 | 0.065 | −0.0035 | −0.50 |

短い窓では仮説の方向に少し効いている（RankICがプラス）。
ただ為替は方向が頻繁に変わるので、セクター配分が何度も反転して回転率が上がり、
コストに負ける。

## 改善案

- 切り替えの強さ（`w`の値・変化）を変える
- 標準化の窓を1年・5年にする
- 水準ではなく変化（前年同月比）で局面を測る
- クオリティ／バリュー以外のファクターについて考える。景況感が悪いときに小型は売られるのか、など。
