## 1. タスク

初回メッセージ末尾の **【実測結果】** を読め。現行の採用版は **v5**（v4/S5 = K1 + Ridge 0.6 +
model_weight 0.25 + span 20 に、`blocks` 明示上書きで `size_pure {"logsize": -1}` weight 2.5 を追加）で、
Train OOS +2.286 / Valid +1.215。第二目標 Valid +1.5 に向けて、今回は
**手動で決めている合成重みを学習で決める仕組み（A）**と、**LGBM とは別種の線形成分（B）**を追加する。
どちらも**既定 OFF** で、既定のままなら v5 と予測がビット一致すること。

### A. 学習型合成 `combo_fit`（None | "ridge"。既定 None = OFF）

現状の合成は「ブロック重み × ブロック z + model_weight × モデル z + sector_weight × セクター中立 z」を
**手動の重み**で足している（重みはローカルの OOS グリッドで決定）。`combo_fit: "ridge"` のときは、
この合成を**学習期間内のリッジ回帰で学習した係数**に置き換える。

1. 学習（`fit_model` または `fit_extras` の中。既存の LGBM / Ridge / rank の学習後）:
   - 説明変数 X（学習期間の行、すべて同日断面 z に正規化）:
     `[z(block_b) for b in resolve_blocks(config)] + [z(モデル予測 after model_smoothing_span)]`
     `+ ([z(モデル予測 − 業種平均)] if sector_neutral)`。
     ブロックは `block_part` と同じ z（`xsec_z`）。モデル予測も予測時と同じ平滑化・z を使うこと。
   - 目的変数 y: horizon ごとに分けて回帰する（k126 と k250 で係数を別々に持つ）。
     ラベルは学習に使ったもの（clip 後）を `label_transform` の変換込みで。horizon_combine の
     予測時平均と整合させる（予測時は horizon ごとの合成値を z 化して平均、という現行と同じ流れ）。
   - リッジの正則化は既存 `ridge` セクションの `alpha` を流用してよい（`label_demean` は適用）。
   - 係数は `model["combo"] = {"columns": [...], "coef": {horizon: [...]}, "intercept": {horizon: ...},
     "rows": {horizon: n}}` の形で凍結し、`meta_v2.json` にも保存する。
2. 予測（`predict_signal` と `submission.py` が共有する関数にすること）:
   - `combo_fit` が ON のときは手動重み（block_weights / model_weight / sector_weight）を**使わず**、
     X @ coef を使う。ブロック z・モデル z・セクター中立 z の作り方は学習時と完全に同じにすること。
   - 既存の `predict_signal` / `add_model_terms` / `ensemble.combine` / `submission.predict_split` の
     流れを壊さない。OFF のときは 1 ビットも変わらないこと。
3. 注意:
   - `combo_fit` ON のときも `ensemble_weights`（lgbm / ridge / rank）の合成はそのまま使ってよい
     （combo はその後の仕上げ合成を置き換える）。どちらの解釈を採ったか Assumptions に書くこと。
   - 学習時間: 説明変数は十数本のリッジ回帰なので 1 秒未満。学習全体を 10 分/フォールド以内に保つ。

### B. 線形成分 `ensemble_weights.linear`（既定 0.0 = OFF）

LGBM と同じ rank 化特徴量（`model_features` の列）を使う**リッジ回帰**を新しいアンサンブル成分として追加する。

1. 学習（`fit_extras` かその近く。`ensemble_weights(config)["linear"] != 0.0` のときだけ）:
   - 既存 `ensemble.fit_ridge` の考え方を流用し、`fit_linear(ranked_features, labels, cfg, clip,
     sample_weight=None)` を作る（`ranked` は `rank_for_model` の出力。SECTOR_COLUMNS はコードのまま
     入れてよい）。horizon ごとに 1 本、全学習期間をプールしたリッジ。
   - 既定パラメータは `ensemble.DEFAULT_LINEAR = {"alpha": 10.0, "label_demean": true}` を新設し、
     config の `linear` セクションで上書き可能にする。
   - `sample_decay_halflife` があれば LGBM と同じ重みを渡す（`fit_ridge` の実装を参考）。
2. 予測:
   - `ensemble.predict_linear(ranked, model["linear"])` を追加し、既存の `predict_ridge` と同じく
     予測値の Series を返す。`ensemble.combine` に `linear` を足す（`ensemble_weights` に `linear` を
     追加。既定は 0.0。重み 0 のときは学習も推論もしない = 従来とビット一致）。
   - `submission.py` も同じ成分を読めるようにする（重み 0 なら従来どおり読まない）。
3. `tools/sweep_improve2.py` の成分（`p_linear`）と再合成（compose）に `linear` を足すと
   ローカル検証が楽になる（この repo の現行版を参考に追加）。

> 参考: v5 は `blocks` を明示上書きして `size_pure` を使っている（`walkforward_config.json`）。
> P8 の変更でこの構成の意味が変わらないこと。
