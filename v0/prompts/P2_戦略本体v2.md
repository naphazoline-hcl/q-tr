## 1. API 契約（`tools/walkforward.py` がそのまま呼ぶ）

```python
build_features(splits=("train",), start=None, end=None) -> pd.DataFrame
    # index=(Date, Code)。P1 の alpha_features.build_features をそのまま呼んでよい。
make_label(k, start=None, end=None) -> pd.Series
    # 翌日から k 営業日の平均残差リターン。窓（t 〜 t+k-1）が end を超える行は NaN。
    # target_1day_train.parquet のみを使う（Valid のラベルを読まない）。
fit_model(features, labels, params) -> dict
    # labels は列が "k126", "k250" のような DataFrame。学習済みモデル一式を dict で返す。
predict_signal(features, model, params) -> pd.Series
    # 合成済みの生シグナル（平滑化前）。index は features と同じ。
```

`params` は `walkforward_config.json` の `params` 節が渡される。`alpha_v2.py` が
import される場所（`strategies/v0_multifactor/`）に `alpha_features.py`（P1 成果物）が
置かれている前提で、`from alpha_features import build_features as build_v2, SECTOR_COLUMNS`
として使ってよい。ただし P1 の出力と独立して読めるよう、必要な補助関数（`xsec_z` 等）は
このファイル内に最小限だけ再定義せよ（P1 の URL も参照すること）。

## 2. 設計要件

### ラベル設計（最重要・コストへの対処）
- 1日先リターンではなく、**翌日から k 営業日の平均残差リターン**をラベルにする。
  モデルが数ヶ月スケールの優劣を学ぶことでシグナルがゆっくり動き、回転率とコストが減る。
- 候補 `k ∈ {63, 126, 250}`。最低でも 126 と 250 の2本は残すこと。
- 外れ値対策: `clip(label, −0.05, +0.05)`（クリップ幅は `params` で変更可能に）。
- 追加の検討（採用可否を `MODEL_DESIGN.md` に理由つきで記録）:
  - ボラティリティで割ったラベル（`label / vol60`）→ 大ボラ銘柄の支配を抑える
  - ランク化ラベル（順位への回帰）→ 外れ値耐性

### モデル
- LightGBM 回帰を基準にする。学習前の特徴量は日次断面で順位化（0〜1）し、
  セクター・市場区分列（`sector17, sector33, market, margin`）は
  `categorical_feature` として素通しにする（v1 と同じ）。
- ベースのハイパーパラメータ（`params.model_params` で上書き可）:

```json
{"objective": "regression", "n_estimators": 350, "learning_rate": 0.03,
 "num_leaves": 31, "min_child_samples": 300, "subsample": 0.8, "subsample_freq": 1,
 "colsample_bytree": 0.7, "reg_lambda": 1.0, "max_bin": 127, "n_jobs": -1, "verbose": -1}
```

- `params.seeds`（既定 `[0, 1, 2]`）ごとに学習し、予測は平均する。
- モデル数は `len(horizons) × len(seeds)` 本。1フォールドの学習は合計 5 分以内を目標。

### セクター中立化（新規・重要）
- ベースライン v1 は業種への偏りを持ち、2020〜2021年のグロース相場で負けた
  （Valid 年別: 2020 −0.32 / 2021 −0.51、2018-2021 サブ期間 +0.38）。
- 以下を実装する:
  1. **ファクター側**: 規模・バリューブロック内の各特徴量について、`sector33` 内の順位に
     変換した版も作り、ブロック平均に加える（`size_in_sector33` は P1 で作成済み）。
  2. **モデル側**: 学習特徴量にセクター列を素通ししたうえで、
     モデル予測を `sector33` ごとに中心化（`x - group_mean`）した版も合成できるようにし、
     `params["sector_neutral"]: true/false` で切り替え可能にする（既定 true）。
  3. `params["sector_weight"]`（既定 0.5）で中立化モデルの寄与を調整可能にする。

### 合成（ブロック + モデル）
```python
signal = w_size*z(size) + w_value*z(value) + w_quality*z(quality) + w_lowrisk*z(lowrisk)
       + w_model*z(model) + (sector_neutral ? w_sector*z(model_centered_by_sector) : 0)
```
- 各ブロックは符号付き断面順位の等ウェイト平均（`signed_block` と同じ方式）。
- 重みの既定値は v1 と同じ（size 1.0 / value 0.5 / quality 0.5 / lowrisk 0.3 / model 0.5 + sector 0.5）。
- すべての重みは `params` で変更可能にする（グリッド探索はローカルで行う）。

### マクロ局面配分（軽量版）
- `consumer_attitude_index` と `topix_vol60` から 2 局面（通常 / 拡張期）を判定し、
  局面ごとにブロック重みを切り替える仕組みを **オプショナル** で実装する。
- 既定は OFF（`params["regime_mix"]: false`）。根拠が弱いまま ON にしないこと。

## 3. `walkforward_config.json`

次を含める。フォールドは 2010〜2015 の各年（`fold_years`）、purge は
最長ホライズン + 10 日（`purge_days: 260`）、平滑化 `smoothing_span: 5`。

```json
{
  "history_start": "2004-01-01",
  "fold_years": [2010, 2011, 2012, 2013, 2014, 2015],
  "horizons": [126, 250],
  "label_clip": 0.05,
  "purge_days": 260,
  "smoothing_span": 5,
  "params": {
    "seeds": [0, 1, 2],
    "model_weight": 0.5,
    "sector_neutral": true,
    "sector_weight": 0.5,
    "regime_mix": false,
    "block_weights": {"size": 1.0, "value": 0.5, "quality": 0.5, "lowrisk": 0.3},
    "model_params": { ... §2 の既定値 ... }
  }
}
```

## 4. 禁止事項（採点で失格になりうる・厳守）

1. `make_label` は `target_1day_train.parquet` のみ読む（Valid のラベルは一切不可）。
   窓が `end` を超える行は NaN（呼び出し側の purge と組み合わせる）。
2. 学習・予測で負の `shift`・`center` rolling・`bfill`・別日付を混ぜた順位化をしない。
3. モデルの入力は `features`（＝P1 の因果的特徴量）に限定する。
4. セクター中心化は**同一日付内**の操作だけにする。
