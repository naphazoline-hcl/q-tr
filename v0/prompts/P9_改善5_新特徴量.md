## 1. タスク

初回メッセージ末尾の **【実測結果】** を読め。現行の採用版は **v7**（Train OOS +2.4667 / Valid +1.3989）で、
予測側の再配合まで済んでいる。ただし直近のローカル探索で、既存の特徴量・ブロック定義・モデル容量・
レジーム・短期ラベルはすべて改善しなかった。**第二目標 Valid +1.5 に向けて、まだ使っていない生データから
新しい特徴量グループを追加する。**

`strategies/v0_multifactor/alpha_features.py` の既存 94 列は**値も順序も一切変えず**、その末尾に
**下記 14 列をこの順で追加**する。現行モデルは `model_features: "v1"`（既存 51 列）なので、既定では
予測は完全に不変（新列はローカルで選抜する）。

### A. 価格系（7列）— `FEATURE_GROUPS["limit_tail"]`

`raw` は `raw_return_1day` の `Return`（既存 `_price_block` と同じ系列）。`UpperLimit` / `LowerLimit` は
0/1 フラグ（価格が制限値幅に達した日。実データ確認済みで train に 529 / 343 件）。`MorningVolume` /
`AfternoonVolume` は出来高の前場・後場内訳（欠損 約0.2%）。`PRICE_COLUMNS` に
`UpperLimit` / `LowerLimit` / `MorningVolume` / `AfternoonVolume` を追加して読むこと。

1. `limit_up20`: 過去 20 営業日の `UpperLimit == 1` の回数（銘柄ごと rolling sum、min_periods 15）
2. `limit_dn20`: 同 `LowerLimit == 1`（min_periods 15）
3. `limit_up60`: 過去 60 営業日の `UpperLimit == 1` の回数（min_periods 45）
4. `limit_dn60`: 同 `LowerLimit == 1`（min_periods 45）
5. `maxret20`: 過去 20 営業日の `raw` の最大値（min_periods 15）
6. `minret20`: 同最小値（min_periods 15）
7. `mvol_share20`: `MorningVolume / (MorningVolume + AfternoonVolume)` の過去 20 営業日平均
   （分母 > 0、min_periods 15）

### B. 財務・キャッシュ系（4列）— `FEATURE_GROUPS["cash"]`

既存の `_load_fins` / `_asof_fins` の backward as-of + ffill 方式に従う。読む生列を
`FINS_COLUMNS` に追加してよい（`OrdinaryProfit` / `CashFlowsFromInvestingActivities` /
`CashAndEquivalents` / `NumberOfTreasuryStockAtTheEndOfFiscalYear`。既存列の式には影響させない）。

8. `cfi_ta`: `CashFlowsFromInvestingActivities / TotalAssets`（TotalAssets > 0 のときのみ）
9. `cash_ta`: `CashAndEquivalents / TotalAssets`（同上）
10. `buyback_chg`: 自己株比率 `tr = NumberOfTreasuryStockAtTheEndOfFiscalYear / SHARES_COLUMN` の
    前年差 `tr - tr.shift(250)`（as-of 展開後の日次系列で。増加 = 自社株買い）
11. `shares_chg`: 発行済株式数の前年比 `SHARES_COLUMN / SHARES_COLUMN.shift(250) - 1`
    （as-of 展開後の日次系列で。希薄化・増資）

### C. ガイダンス系（3列）— `FEATURE_GROUPS["guidance"]`

12. `op_fwd_yoy`: `ForecastOperatingProfit / op_ttm - 1`（`op_ttm > 0` のときのみ。予想ベース増益率）
13. `ord_op_gap`: `(OrdinaryProfit - OperatingProfit) / NetSales`（NetSales > 0。営業外損益の割合）
14. `nsales_fwd_yoy`: `NextYearForecastNetSales / ForecastNetSales - 1`（両方 > 0 のときのみ。
    翌期予想の増収率。`NextYearForecastNetSales` は疎だが NaN のままでよい）

### D. 実装要件

- `FEATURE_GROUPS` に上記 3 グループを追加し、`NEW_COLUMNS` / `ALL_COLUMNS` の**末尾**に A→B→C の順で入る。
  既存 94 列の値・順序・式は不変（後方互換）。
- 時点管理は既存の規約どおり: 負の shift・center rolling・bfill 禁止、順位化は同一 Date の断面のみ、
  財務は開示日基準の backward as-of。`end` を渡したときの truncation invariance を新列も満たすこと
  （rolling は `_rolling` と同じ過去方向のみ、as-of は `Date <= end`）。
- すべて float32。値が全期間 NaN になる列を作らない。分母 0 は NaN。
- 新列は `model_features: "v2_slow" | "all" | 明示リスト` のときだけモデルに入る。既定
  `model_features: "v1"` の walkforward / 推論結果がビット一致することを確認すること。

### E. 検証・成果物

- `selftest_p9.py`（合成データ・実データ不要）を追加:

     読み、同じ入力パネルで比較。`np.array_equal`）。

  3. 因果性: 入力の末尾を切って `build_features(end=cut)` した結果が、全期間版の `Date <= cut` 行と

  4. 新列だけを `model_features` に渡した合成 walkforward が動く（任意）。

## 5. Assumptions（不明点をここに書く）

- 生列の型・欠損は `docs/data_schema.md` を正とする。実データ確認で判明している事実:
  `UpperLimit` / `LowerLimit` は 0/1 フラグ（まばら）、`MorningVolume` / `AfternoonVolume` は 0.2% 欠損。
- 財務の新しい生列は既存 `FINS_COLUMNS` と同様に ffill してから式に使う。TTM 化は不要（分母は
  TotalAssets / NetSales / op_ttm など既存の系列を使う）。
- `op_ttm` は既存 `TTM_ITEMS` の出力（`OperatingProfit` の TTM）。`ForecastOperatingProfit` は
  通期予想の ffill 系列。
- セッション出来高の欠損日は `mvol_share20` の平均から除外される（`skipna`）。
