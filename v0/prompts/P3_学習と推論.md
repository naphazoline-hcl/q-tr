# P3: 学習と推論の実装（`train_v2.py` + `submission.py`）

## 0. 出力形式（厳守・最初に読め）

- 応答は**単一の React Web アプリ（1つのコードブロック）のみ**。素の文章だけの応答は禁止。
- アプリには次の3ファイルの**全文**を埋め込み、**ファイルごとのコピー＋個別ダウンロード**と
  **JSZip による一括ZIP（`train_submit_package.zip`）**を付けること。
  - `train_v2.py` … 全 Train データで最終モデルを学習し、`models_v2/*.txt` と `meta_v2.json` を書く
  - `submission.py` … 推論のみ（`meta_v2.json` + `models_v2/*.txt` を読んで予測を返す）
  - `TRAINING.md` … 学習の手順書（必要なコマンド・所要時間の目安・再開方法、1ページ）
- **25分で完成しない場合は、完成したファイルだけでも先に出力せよ**。
- すべて日本語で出力（コード内コメントのみ英語可）。不明点は質問せず Assumptions 節に記録。
- **数値の捏造禁止**。

## 1. タスク

P2 の戦略本体（`alpha_v2.py`）を使って、

1. 全 Train データで最終モデルを学習する `train_v2.py` を作る
2. 学習済みモデルを読んで Valid の予測を返す `submission.py` を作る（提出対象）

ローカル側の検収フロー（人間が実行する・参考情報）:

```bash
python strategies/v0_multifactor/train_v2.py --strategy strategies/v0_multifactor
python tools/score.py --submission strategies/v0_multifactor --split train
python tools/score.py --submission strategies/v0_multifactor --split valid --guard
python tools/check_lookahead.py --submission strategies/v0_multifactor --runtime
```

## 2. `train_v2.py` の要件

- `alpha_v2.make_label(k, start=..., end=None)` でラベルを作り、
  `alpha_v2.fit_model(features, labels, params)` で学習し、
  `models_v2/lgbm_k{k}_s{seed}.txt` に **1本終わるごとに保存**する。
- **進捗ファイルが必須**（`tools/progress.py` の `Progress` を使う。import のために
  `sys.path` へ `tools/` を追加する）。`--resume` を付けると既存モデルを読み飛ばす。
- 使い方: `python train_v2.py --strategy <戦略フォルダ> [--resume]`。
  戦略フォルダの `walkforward_config.json` を読み、`horizons` / `seeds` /
  `params` をそのまま使う（設定のコピペはしない）。
- 終了時に `meta_v2.json` を書く: `model_files` / `features`（モデルが期待する列名の順序つき）/
  `sector_features` / `horizons` / `seeds` / `label_clip` / `smoothing_span` /
  `model_weight` / `sector_neutral` / `sector_weight` / `regime_mix` / `block_weights` /
  `training_rows` / `training_from` / `training_to`。
- 学習時間の目安を `TRAINING.md` に書く（行数 × 本数から見積もる）。

## 3. `submission.py` の要件（提出物そのもの）

- `predict()` は `(Date, Code)` を index に持つ **1列の DataFrame** を返す。
- **採点対象（`raw_return_1day_valid.parquet` と `target_1day_valid.parquet` の index の合併）**
  を完全に覆うこと。不足があるとエラーになる。
  具体的には `target_1day_valid.parquet` の index（**採点では配布されない**ので、
  `raw_return_1day_valid.parquet` の index との合併で再現する）を返す。
- メモリ・時間の必須対策（採点は30分以内・非力な環境の可能性）:
  - parquet は `columns=[...]` と `filters=[("Date", ">=", HISTORY_START)]` で絞る
    （`HISTORY_START = 2014-06-01` 相当、250営業日超の余裕を持たせる）。
  - `listed_info` は必要5列（`ScaleCategory`, `Sector17Code`, `Sector33Code`,
    `MarketCode`, `MarginCode`）のみ。`features` の順位化は float32 のまま in-place で行う。
  - `lgb.Booster(model_file=...)` でモデルを読み、`meta_v2.json` の列順序で
    DataFrame から予測する（列名の不一致はエラーで停止）。
  - 最後に銘柄ごとの EWMA（`smoothing_span`、v1 では 5）で平滑化する。
- 予測コードは配布 parquet を**ベース名で相対読み**する（cwd = データ展開先の前提）。
  同梱ファイル（`meta_v2.json` / `models_v2/*.txt`）は `Path(__file__).resolve().parent` 基準で読む。
- **予測コードから `target_1day_*` / `raw_target_1day_*` を読まない**。
  （ラベルが必要なのは学習コードだけ）。
