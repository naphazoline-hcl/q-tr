## 1. タスク

初回メッセージ末尾の **【実測結果】** を読め。現行の採用版は v4/S5（K1 + Ridge アンサンブル
`ridge: 0.6` + `model_weight: 0.25` + `model_smoothing_span: 20`）で、Train OOS +2.124 / Valid +0.803。
**rank 併用・span 微調整・slow_profile はローカルで実測済みで効果が無かった**ため、今回は
**新しいブロック（別のアルファ源）**と**学習のロバスト化**で Valid +1.2 を狙う。

### A. 新ブロック（`block_set: "v3"` を追加。既定の "v1" は不変）

`alpha_v2.BLOCK_SETS` に `"v3"` を追加する。既存 v1 の 4 ブロック（size / value / quality / lowrisk）を
**そのまま維持**し、次の 3 ブロックを足す（各列の意味と向きは `alpha_features.py` の計算式を読んで確認し、
符号の根拠を CHANGELOG に書くこと）:

- `momentum`: `rcc120` +1.0, `rcc250` +1.0, `mom` +1.0, `res250` +1.0（12 か月モメンタム系）
- `revision`: `eps_revision` +1.0, `opprofit_revision` +1.0, `eps_fwd_chg` +1.0,
  `sales_yoy_acc` +1.0, `op_margin_yoy_chg` +1.0（業績修正・成長系）
- `liquidity`: `illiq20` +1.0, `illiq60` +1.0, `logturn20` -1.0, `logturn60` -1.0（流動性）

ルール:
- `block_weights` には新ブロックを追加しない（既定の重み 0 = 直接合成には効かない）。
  ただし **Ridge の説明変数は `block_scores` の全ブロック**（`ensemble.fit_extras` が全ブロック z を渡す）
  なので、`block_set: "v3"` にすると新ブロックは Ridge 経由で自動的に使われる。これが狙い。
  `block_weights` を設定すれば直接合成にも使える（ローカル sweep で両方を試す）。
- `BLOCK_SETS["v1"]` / `["v2"]` は変更しない。`sector_rank_blocks` の既定も変更しない。

### B. 学習のロバスト化（新キー 2 つ、既定 OFF）

1. `sample_decay_halflife`（None | 日数。既定 None）:
   学習サンプルの重みを `w = 0.5 ** (経過日数 / halflife)` にする。経過日数は
   「学習期間の最終 Date − その行の Date」（学習期間内のみ。未来は見ない）。
   LGBM は `sample_weight`、Ridge は重み付き最小二乗、rank モデルがあれば同様に渡す。
2. `feature_top_k`（None | 整数。既定 None）:
   学習を 2 パスにする。1 パス目は今までどおり全列で（horizon, seed）の LGBM を学習し、
   列ごとの gain importance を正規化 → horizon×seed 間で平均順位を計算 → 上位 k 列を選ぶ
   （`SECTOR_COLUMNS` は常に残す。カテゴリ列は落とさない）。2 パス目は選択列だけで最終モデルを学習し、
   `fit_model` の `result["columns"]` を選択列にする。`train_v2.py` / `submission.py` /
   `meta_v2.json`（`features`）は選択列で一貫させる（rank モデルも同じ列）。
   None なら 1 パス（従来どおり）。
   - 注意: `rank_for_model` / `model_prediction` / `submission.ranked_matrix` は
     `model["columns"]` / `meta["features"]` をそのまま使うので、選択列の受け渡しを壊さないこと。

### C. 検証・成果物

- `selftest_p7.py`（合成データ・実データ不要）:
  1. 既定 OFF で v4/S5（このリポジトリの現行 alpha_v2.py）と新版のシグナルが一致するか（`--reference` 方式）。
  2. `block_set: "v3"` / `sample_decay_halflife: 250` / `feature_top_k: 20` が設定だけで ON/OFF でき、
     シグナルが変わること。
  3. 因果性: 予測期間の後半を切り落としても前半のシグナルが変わらないこと（全部 ON で検査）。
- `CHANGELOG_v4v5.md`（変更点・根拠・既定値）と `REPORT_P7.md`（Assumptions・時間見積もり）。

## 2. 制約（厳守）

- API 契約・既存キー（`ensemble_weights` / `regime_weights` / `turnover_cap` / `slow_profile` 等）は維持。
- **既定値のままなら現行 v4/S5 と予測がビット一致**すること（`feature_top_k` None・`sample_decay_halflife`
  None・`block_set` 既存値のとき）。sweep_improve2 の再合成とも整合させる。
- `feature_top_k` ON の学習は 2 パスになるため、**1 フォールド学習 ≤ 10 分**に収まる見積もりを出す
  （収まらない場合は `n_estimators` 調整や選択の簡略化で対応）。推論は ≤ 30 分。
- 禁止パターンなし・Valid ラベルを読まない。LightGBM は 4.1.0 固定（numpy 2 の copy 例外に注意）。
