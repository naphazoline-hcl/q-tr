- すべて日本語で出力（コード内コメントのみ英語可）。不明点は質問せず Assumptions 節に記録。

## 1. タスク

初回メッセージ末尾の **【実測結果】** を読み、P4 までで取りきれていない弱点を
**モデル多様化と局面配分**で攻める。狙いは Valid Sharpe +1.2 以上。

### A. モデルの多様化（必須）
ベースラインは LightGBM 回帰のみ。次を追加し、予測を合成する:
1. **線形リッジ**（`sklearn.linear_model.Ridge`）: ファクターブロック平均を特徴量に、
   係数は断面ではなく時系列で学習（過去全体のパネル回帰）。非線形モデルの補完として効く。
2. **分位回帰または順位回帰**（LightGBM の `objective: quantile` / `lambdarank`）:
   採点が順位（5分位）で行われるため、順位を直接最適化する損失の寄与を検証できるようにする。
   （採点環境の LightGBM は CPU 版 4.1.0 のため、`lambdarank` の学習時間に注意。
   既定は OFF、切替フラグで ON にできること。）
3. すべての予測は **日次断面で z 化してから合成**（水準の違いを無効化）。
   合成重みは `params["ensemble_weights"]`（例: `{"lgbm": 1.0, "ridge": 0.3, "rank": 0.0}`）で調整可。

### B. 局面配分（P2 の軽量版を本格化）
- `params["regime_mix"]: true` で有効化できる本格版を実装する。
- 局面は **マクロ2変数**（`consumer_attitude_index` の水準・変化、`USD/JPY` の変化率）
  と **市場2変数**（`topix_cum60`、`topix_vol60`）から、**因果的なルール**で 2〜3 局面に分ける。
  （ルール例: 消費者指数が低下トレンド + ボラ高止まり → 回避局面で低リスク寄与を上げる）
- 局面ごとのブロック重みを `params["regime_weights"]` に持つ。
  局面判定は **同一日付までの情報のみ**で行う（未来の局面で重みを選ばない）。
- 既定は OFF。ON/OFF の両方でローカル walk-forward が回せる実装にすること。

### C. 低速シグナル化の徹底（回転率対策）
- 日次回転率の上限を `params["turnover_cap"]` として宣言し、EWMA span を
  5 / 10 / 20 のどれにするか **ラベル設計とセットで** 選べるようにする。
- 平滑化は銘柄ごとの EWMA（未来を見ない）を維持する。

## 2. 制約（厳守）

- API 契約・設定キーは維持（`ensemble_weights` / `regime_weights` / `turnover_cap` を追加）。
