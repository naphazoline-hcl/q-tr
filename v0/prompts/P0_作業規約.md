# P0: 作業規約（v0.app 全プロンプト共通・タイムアウト対策）

> このファイルは P1〜P6 すべてに共通する「どう進めるか」の規約である。
> 各プロンプトの §0.5 から参照される。**着手前に必ず全文を読め。**
> ここに書かれた内容は「何をするか」ではなく「どう進めるか」の指示なので、タスク本文の指示と両立させること。

## 0. 前提（この実行環境の仕様）

- 1メッセージあたり約27分まで作業できる。
- ただし「1回の応答」（あるツール呼び出しから次のツール呼び出しまでに行う思考と出力。Write/Edit に
  渡す本文も含む）が長くなりすぎると、ターン全体が強制終了される（目安は約4分。時間ではなく出力量で
  決まっている可能性もある）。
- 強制終了されても**書き込み済みのファイルは残る**が、最終報告は出ない。
- **ツールを呼ばずに応答を終えると、ターン終了として扱われる**（待機や確認のつもりでも終わる）。

## 1. ターンを終わらせない（最重要）

- 待つだけ・確認を求めるだけの文章で応答を終えない。**待つときは Bash で `sleep 30` を実行**し、
  その後に出力を確認する（待機専用ツールは無い）。
- コマンドの完了は状態表示ではなく**出力**で判定する。終わった後も still running と表示されることが
  あるため、バックグラウンド起動するコマンドは末尾に `echo __DONE__` を付け、`__DONE__` が出たら
  完了とみなす。
- 質問して止まらない。不明点は合理的な前提を置いて進め、その前提を最終報告に書く。
  自力で解決できない場合（認証・外部サービスの接続など）だけ止まってよい。

## 2. 1回の応答を短く保つ

- 1回の応答は1〜2分で終わる量に抑える。途中の進捗報告は1〜2文にする。
- 1回の応答で書き出すコード・文章は**合計200行程度まで**（複数の Write/Edit を並列に呼ぶ場合も合算で数える）。
- 設計全体を頭の中で完成させてから書き始めない。全体方針は数行の箇条書きにとどめ、細部は実装しながら
  決める。
- 大きなファイルは、先に骨格（全体の構成と中身が空の関数）を作り、その後 Edit で機能ごとに書き足す。
  可能ならファイル自体を小さなモジュールに分ける。
- 資料を大量に読んだ直後は特に注意する。読み込みは数件ずつにし、読み終えた直後に全体設計や一括生成を
  しない。小さな実装から着手する。
- 最終報告も簡潔にする。長い文書が必要な場合は、ファイルに分けて書く。

## 3. 時間のかかるコマンド

- 数分かかりそうなコマンド（インストール・ビルド・テスト・データ処理など）は `run_in_background` で
  起動し、短い待機（30〜60秒）と出力の確認を繰り返す。
- コマンドには必ず明示的なタイムアウトを付ける。

## 4. 約27分を有効に使う

- 各ターンの最初の行動として、Bash で `date +%s > /tmp/turn_start` を実行する。
  以後は数ステップごとに `echo "elapsed: $(( ($(date +%s) - $(cat /tmp/turn_start)) / 60 )) min"` で
  経過時間を確認する。
- 経過22分を過ぎたら新しい作業を始めない。作業中のファイルを壊れていない状態にして、25分までに最終報告を
  出す。最終報告には、**完了した内容・未完了の項目・次にやること**を書く。
- 計画を示しただけ・確認を求めただけで止まらない。タスクが早く終わったら、その時点で終えてよい。
  時間を埋めるための作業はしない。

## 5. 途中で打ち切られた場合

- 前のターンが最終報告なしで途切れていたら、**最初からやり直さない**。ファイルの状態を確認して、
  続きから再開する。再開時もこの規約（1応答を短く・アーティファクトを壊さない）に従う。

## 6. 成果物の渡し方（プロンプト側の §0 と併せて守る）

- 成果物はコードブロックに埋め込まず、**Write で実ファイルとして作る**（`deliverables/` など、
  プロンプト §0 の指定に従う）。
- 同時に、成果物を読み込む React Web アプリを作り、**ファイルごとの全文コピー・個別ダウンロード・
  JSZip による一括ZIP**を提供する（回収経路はこれだけ）。
- 受け入れチェックの結果は**最終報告に簡潔に**書く（長い場合は `REPORT.md` に分けてよい）。
- 25分で完成しない場合は、完成したファイルだけでも先に作る（部分成果を許容）。
- **数値の捏造禁止**。不明な数値は `{要実行}` と書く。
