## 4. 実装する特徴量（ブロック別）

### A. 価格・リターン（既存の拡張）
- 52週高値・安値からの位置: `ac / rolling_max(ac,250) − 1`, `ac / rolling_min(ac,250) − 1`
- 残差リターン（市場中立化した過去リターン）: `raw_return − beta × topix_return[t]`
  の累積（20/60/250日）。βと市場は配布列なので先読みなしで作れる。
- ボラの期間構造: `vol5 / vol20`（短期ボラの相対的上昇）
- 上方・下方ボラ比: `dvol60 / uvol60`（上昇日のみのボラを新規に作る）
- 分布形状: `skew20`, `kurt20`, 上昇日比率 `updays60`
- 1次自己相関（60日窓）: `corr(r1, r1.shift(1))`
- 長期リバーサル: `rcc120 − rcc20`, `rcc250 − rcc60`
- ギャップ: `AdjustmentOpen / prev_AdjustmentClose − 1`（既存 `rev_co` と同義なら
  「ギャップの20日平均 `gap20`」を追加）

### B. 流動性・需給
- `logturn20 − logturn60`（売買代金トレンド）
- `illiq5`（Amihud の短期）
- `volume_z20`（20日窓のボリューム z スコア、過去方向のみ）
- `highlow60`（`(High−Low)/Close` の60日平均）
- `valid_ratio20`（20日窓で価格が NaN でない行の比率＝売買停止・欠損の代理変数）

### C. バリュー（TTM 化と基準そろえ）
- **TTM 化（重要）**: `fins_statements` は四半期累計値（`Period` と `CurrentPeriodStartDate/EndDate`
  で期間が分かる）。売上・営業利益・純利益・営業CF について TTM を構成する:
  - 同一会計年度内: `TTM = 今回累計 + 前年FY − 前年同期累計`
  - 会計年度が変わった直後など前年同期が無い場合は、直近の通期実績を使う（`{要実行}` でよい）
  - 各開示行に `*_ttm` 列を追加し、日次パネルへは**開示日基準の as-of** で展開する
- TTM 指標: `ep_ttm`, `sp_ttm`, `cfy_ttm`, `roe_ttm`, `op_margin_ttm`, `accrual`
  （`accrual = (Profit_ttm − CFO_ttm) / TotalAssets`、利益の質の代理）
- 予想と実績の乖離: `ep_f − ep_a`（改訂余地）

### D. クオリティ・成長
- `equity_ratio_chg`（自己資本比率の前年同期差）
- `op_margin_yoy_chg`（営業利益率の前年同期差）
- 成長の加速度: `sales_yoy − sales_yoy_prev`（YoY の変化。`_by_code().shift(250)` を使う）
- 予想配当の方向: `ForecastDividendPerShareAnnual` の前期比変化率 `div_chg`

### E. 予想改訂・開示イベント
- 予想 EPS の改訂率: 1つ前の開示と比べた変化率（開示行ごとに計算し、日次へ as-of 展開）
  `eps_revision = ForecastEarningsPerShare / prev(ForecastEarningsPerShare) − 1`
- 予想営業利益の改訂率 `opprofit_revision`
- 進捗率: `1Q累計実績 / ForecastProfit`（`Period` が 1Q のときのみ意味を持つ）
- 直近開示ダミー `disclosed_5d`（5営業日以内に開示があったか）
- 開示からの経過営業日 `disc_days_bd`

### F. 属性・マクロ・市場状態（参考特徴量）
- サイズの業種内順位 `size_in_sector33`（同日内・同業種内の順位。後段の中立化にも使う）
- マクロ（全銘柄に同じ値をブロードキャスト。`Date` = 利用可能日時の backward as-of）:
  `usdjpy_chg20`, `usdjpy_chg60`, `consumer_level_z`（過去5年の z スコア）, `consumer_diff`
- 市場状態: `topix_cum20`（20日累積）, `topix_vol60`（60日ボラ）

## 5. 実装規約（違反すると採点で失格になりうる）

1. **因果性**: 各時点 `t` の行は `t` までに確定した情報のみ。
   - `rolling` は過去方向のみ（`center=True` 禁止）、`shift` は正のみ（`shift(-1)` 禁止）、
     `bfill` / `backfill` / `limit_area='both'` 禁止、`[::-1]` は**ラベル生成以外では禁止**。
   - 順位化・標準化は**同一 `Date` の断面のみ**。時系列正規化は過去方向の expanding のみ可。
2. **財務の基準そろえ**: `AdjustmentClose` は配布時点（2026-07-31）の株式数基準に調整済み、
   `fins_statements` の1株当たり値は**開示時点の基準**。比率 `R = AdjustmentClose / Close` を
   開示日に as-of で持ち、`1株当たり値 × R(開示日)`、`株式数 ÷ R(開示日)` と換算してから使う。
   v1 の `_asof_fins()` と同じ方式でよい（`_rfactor` 列を流用）。
3. **マクロ結合**: `Date` は「日本時間で利用可能になった日時」、`ObservationDate` は観測日。
   **必ず `Date` で backward as-of**（`ObservationDate` で結合すると先読み）。
4. **メモリ**: parquet は `columns=[...]` と `filters=[("Date", ">=", start)]` で絞る。
   DataFrame のコピーを増やさない。列は float32 で保持。
5. **NaN**: 欠損は未来の値で埋めない。NaN のまま残してよい（下流の `fillna(0)` が中立に落とす）。
6. 新規列は末尾にまとめ、`FEATURE_GROUPS` に分類を定義する:

```python
FEATURE_GROUPS = {
    "price_reversal": [...], "risk_liquidity": [...], "value": [...],
    "quality_growth": [...], "revision": [...], "regime": [...],
}
```

## 6. `selftest_features.py` の要件

- `build_features(splits=("train", "valid"), start=...)` を実行し、次を表示する:
  1. shape・列数・期間・ユニーク銘柄数
  2. 列別 NaN 率の上位20
  3. 主要列の記述統計（mean / std / min / max / 1% / 99%）
  4. **壊れた特徴量の検出**: 全欠損の列、値が全て同一の列、inf を含む列
  5. **簡易因果性検査**: `end="2014-06-30"` で再構築し、`Date <= 2014-06-30` の値が
     全列で一致するか（不一致の列名と最大差を表示）
  6. 実行時間（秒）
- 終了コード: 4 や 5 で問題があれば 1 を返す。
